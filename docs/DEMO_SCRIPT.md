# SmartGuard 答辩演示脚本（约 6 分钟）

> 目标：按"故事线"演示，每个环节都有串口日志作证。提前把本页打印或放在第二屏。

---

## 0. 开场前检查（T-10 分钟）

- [ ] 笔记本热点 `LAPTOP-KNLKBLMS 0997` 已开，手机/其他设备别抢
- [ ] mosquitto 服务已启动（1883 TCP + 9001 WebSocket）
- [ ] 板子上电，串口 COM11 @115200 开着，看到 `SmartGuard v0.7.2` 横幅
- [ ] 看到 `[EVENTLOG] write selftest: PASS`（存储自检）
- [ ] CAM 已上电 ≥20 秒（等它连 WiFi），STM32 日志有 `[INIT] ESP32-CAM...OK (online)`
- [ ] 网页 `localhost:8080` 打开 Dashboard，**DEV / MQTT 双绿灯**
- [ ] 基线已从 EEPROM 恢复（`Restored from FLASH`，跳过 20s 学习）或现场学一次

**应急预案**：
- DEV 灭 → 重新插拔 ESP8266（接触不良高发），等 10s
- CAM offline → 重新插拔 CAM，等 20s 后在网页点一次"手动抓拍"自动重握手
- 网页无图 → 点一次"手动抓拍"刷新 retain 链接

## 1. 开场白（30 秒）

> "这是一个端侧智能的安防原型。普通报警器阈值写死、换房间就误报；
> 我的系统上电自己学环境基线，只在统计显著偏离时告警，
> 并且告警时拍照取证、事件写入黑匣子，断网断电都有自愈设计。"

指网页 About 页（可选）：架构图四层 = 主控 / 通信 / 视觉 / 看板。

## 2. 实时监控（40 秒）

- 指 Dashboard 五张传感器卡片：温/湿/光/距离/MQ2 实时刷新（10s 遥测）
- 指顶栏：`AW` 离家模式；DEV/MQTT 绿灯含义（链路分段诊断）
- 话术："数据链路是 STM32 → ESP8266 → 手写 MQTT 报文 → broker → 网页，没有用一个现成 SDK"

## 3. 入侵告警全链路（90 秒，核心环节）

1. 手从超声波前挥过（距离 < 40cm 硬阈值）
2. **同时**指出四个联动：
   - 蜂鸣器三连音（入侵专属，与火灾/防拆音色不同）
   - 网页页面红边闪烁 + 告警时间线新增一条"入侵"
   - CAM 自动抓拍，约 2 秒后卡片出新照片
   - 串口 `!!INTRUSION!!` + `[ESP32-CAM] photo: http://...`
3. 再挥两次（间隔 >5s）：胶片条累积多张，点缩略图回看——
   话术："最后一张往往人已离开，所以保留了 12 张历史环，拍到人的是中间某张"
4. 展示 W25Qxx 落盘：按 **S4 长按 1.5 秒**，串口回放事件（时间戳 + 现场光照/烟雾/距离）
   话术："这是断电不丢的黑匣子，板载 SPI FLASH 环形存储 1024 条"

## 4. 防拆 + 远程控制（60 秒）

1. 拿起/晃动开发板 → 防拆告警（低沉长音），时间线出"防拆"（橙色）
   话术："陀螺仪零偏自校准 + 滑窗投票，碰一下不误报，连续晃才报"
2. 网页 CONTROL 演示：
   - 点 LED 开关 → 板载 PE13 灯亮灭（retain 状态同步）
   - 切模式 HO/AW/SL → OLED 同步变、TopBar chip 同步变
   - 点"告警测试" → 等价 S4 短按，完整链路再来一遍
   - 点"手动抓拍" → 无告警也能拍照（刚才 CAM 重插恢复也是它）
3. 板载按键 S1/S2/S3 切模式 → 网页同步（双向）

## 5. 历史与 AI（60 秒）

1. History 页：距离曲线上红色虚线 = 告警时刻，与下凹一一对应
   话术："历史本地分层存储：2 小时内 10 秒原始点，更早压成 5 分钟均值，能看 7 天"
2. AI 话术（不用现场触发，串口有 `[AI] TinyML MLP 已启用` 即可）：
   > "AI 分三层：硬阈值管确定的（<40cm 必报）；自适应基线用 EWMA 统计学习自己维护，
   > 不用人工调阈值；40~80cm 模糊地带交给 sklearn 训练的 MLP 神经网络端侧推理，
   > 一次 <1ms。规则守住可解释性，AI 处理模糊性。"

## 6. 自愈设计收尾（40 秒）

口述（日志都有证据）：
- 存储：`write selftest: PASS`——开机自检；课程板遗留的 WPS 写保护锁自动解除
- 断网：MQTT 自动重连，重连阻塞期间防拆采样由 WaitHook 续采不中断
- 掉电：配置在 EEPROM、事件在 FLASH、写指针在纽扣电池备份 SRAM、RTC 继续走时
- 看门狗：IWDG 2s，所有长阻塞分段喂狗

## 7. 预设问答

| 问 | 答 |
|---|---|
| AI 在哪？ | TinyML MLP 端侧推理（边界分流）+ EWMA 自适应基线（统计学习）+ 滑窗投票（震动识别），全部本地运行 |
| 为什么不用 RTOS？ | 课程要求 + 协作式调度器足够：任务表注册、周期零漂移、空闲 `__WFI` 休眠，代码量小一个数量级 |
| 断网了告警还有吗？ | 有。决策全在端侧，网络只负责通知；事件照写黑匣子，网络恢复后 MQTT 自动重连 |
| 照片存哪？会丢吗？ | CAM 内存 12 张环（断电丢，属缓存）；告警事件本身（时间戳+传感器快照）在 W25Q128 断电不丢 |
| 阈值怎么定的？ | 上电 20s 学习均值±σ，EWMA 慢漂移跟踪环境；MQ2 预热期的坏阈值会自愈重建 |
| 时间从哪来？ | NTP 对时到 RTC，纽扣电池保持；失败回退编译时间 |

## 8. 绝对不要现场演示的

- 重新编译/烧录（任何最后一分钟的代码改动）
- 拔插任何线缆（除非按预案排障）
- 长时间开 LIVE 实时画面（占 ESP32 单客户端，演示完及时切回）
