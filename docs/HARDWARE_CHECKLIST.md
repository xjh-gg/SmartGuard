# SmartGuard 硬件检查清单

> 基于 SmartGuard v0.4+ 项目实际踩坑经验整理，用于每次硬件变更、换板、换模块后的快速自检。

---

## 1. 核心模块规格速查

| 模块 | 型号/协议 | 关键参数 | 必查项 |
|------|----------|---------|--------|
| MCU | STM32F407ZE | 168MHz, 3.3V GPIO | 所有 IO 不得直接接 5V（除 5V-tolerant 引脚如 PB0/PB1） |

## 2. 各模块专项接线与排错

### 2.1 OLED 显示屏

> 最容易出问题的模块，务必逐项确认。

#### 引脚对应（8 脚模块，从左到右）

| OLED 丝印 | 接到开发板 | 备注 |
|----------|-----------|------|
| GND | GND | 共地 |
| VCC | **5V** | 3.3V 可能也能工作，但卖家推荐 5V |
| CLK | PB0 | SPI 时钟 |
| MOSI | PF11 | SPI 数据（MCU→OLED） |
| DC | PB1 | 命令/数据选择 |
| CS1 | PC13 | OLED 片选 |
| FSO | **悬空** | 字库芯片输出，不用 |
| CS2 | **VCC** | **必须接 VCC** 禁用 GT20L1616 字库芯片 |

#### 不亮排查流程

```
1. 量 VCC-GND 电压是否为 5V
   └─ 否 → 检查电源接线
   └─ 是 → 下一步

2. 确认 CS2 已用杜邦线接到 VCC（不是悬空）
   └─ 否 → 短接 CS2 到 VCC
   └─ 是 → 下一步

3. 确认 PC13 没有被 RTC Tamper 占用
   └─ 检查串口是否有 [RTC] 日志，确认 rtc.c 中已禁用 Tamper
   └─ 若 RTC 初始化在 OLED 之后，PC13 会失效 → 调整初始化顺序

4. 检查 SPI 时序是否过慢/过快
   └─ F407 @168MHz 软件 SPI 必须用 delay_us(1)，不能用 __nop()
   └─ 参考 Hardware/OLED/oled.c 当前实现

5. 用卖家提供的 STM32F103 例程单独烧录测试 OLED
   └─ 若卖家例程也不亮 → OLED 模块硬件损坏
   └─ 若卖家例程能亮 → 对比初始化序列和 SPI 时序
```

### 2.2 HC-SR04 超声波测距

#### 接线

| HCSR04 | 开发板 | 备注 |
|--------|--------|------|
| VCC | **5V** | **必须用 5V**，3.3V 无回波 |
| GND | GND | 共地 |
| Trig | PC8 | GPIO 推挽输出 |
| Echo | PC6 | TIM8_CH1 输入捕获 |

#### 常见问题

- **距离始终为 0 或 268cm 左右**：检查 VCC 是否为 5V；检查 Trig/Echo 是否接反。
- **读数跳变很大**：增加采样平均次数；检查探测面是否平整。
- **近距离（<3cm）不准**：HC-SR04 盲区约 2cm，属于硬件限制。

### 2.3 ESP8266 WiFi 模块

#### 接线

| ESP8266 | 开发板 | 备注 |
|---------|--------|------|
| VCC | 3.3V（部分模块支持 5V） | 按模块丝印供电 |
| GND | GND | **必须共地** |
| RXD | PB10 (USART3_TX) | |
| TXD | PB11 (USART3_RX) | |
| CH_PD/EN | 接 VCC | 使能脚，必须拉高 |

#### 常见问题

- **串口无 AT 响应**：检查波特率是否为 9600；确认 CH_PD 已接 VCC；换一根 USB 线排除供电不足。
- **所有 AT 指令均 0 字节应答（115200/9600 双波特率探测全失败）**：先别判模块死刑。2026-09-20 实测一例：固件侧 `AT`/`AT+RST`/`AT+CIPCLOSE` 全部 0 字节、持续一整天，最终原因是**排针接触不良**——拔下模块重新插紧即恢复。**排查顺序：重新插拔模块 → 换杜邦线 → 查 CH_PD 上拉 → 查供电 → 最后才怀疑模块损坏**。虚接的成因多为面包板/排母簧片疲劳，震动（防拆测试晃动板子）后高发。
- **能连 WiFi 但 UDP 发送失败**：电脑防火墙可能阻挡 UDP；确认电脑已连接同一热点并运行接收脚本。
- **频繁掉线/重启**：供电电流不足，ESP8266 峰值可达 300mA，建议独立供电或换好的 USB 口。
- **UDP 报文重复发送**：`ESP8266_SendAlert` 有 5s 冷却，连续触发时只发一次，属于正常保护逻辑。

### 2.4 ESP32-CAM 摄像头联动

#### 接线

| ESP32-CAM | 开发板 | 备注 |
|-----------|--------|------|
| 5V | **5V** | **必须 ≥500mA**，否则自动重启 |
| GND | GND | 共地，**必须接真 GND 针**（见下方针脚陷阱） |
| U0R (GPIO3) | PA2 (USART2_TX) | |
| U0T (GPIO1) | PA3 (USART2_RX) | |

#### 针脚陷阱（2026-09-18 实测踩坑记录）

AI Thinker ESP32-CAM 下排（U0R/U0T 所在排）针序为：

```
3V3 | IO16 | IO0 | GND | VCC | U0R | U0T | "GND"（角落）
```

有两个**假针**，接错表现为"CAM 单独供电正常，一接 STM32 共地就死/串口全灭"：

1. **角落"GND"针（U0T 隔壁）= GND/R 复位陷阱**：很多批次的这根针不是地，而是经电阻接 EN/复位。把它接到 STM32 GND，CAM 被永久按在复位态——程序不跑、串口沉默。诊断特征：不接这根线 CAM 正常，一接就"死"。
2. **`VCC` 针 = 3.3V 输出，不是地也不是电源输入**：它正好夹在真 GND 和 U0R 之间，最容易认错。误当 GND 接会把 CAM 的 3.3V 轨对地短路；误当电源输入则 CAM 不启动。

**真 GND 只有两根可用**：上排第 2 针（5V 隔壁）、下排中间针（IO0 与 VCC 之间）。

**推荐排查工具**：烧一个"上电亮灯 + 串口每 2s 广播字母"的测试固件（GPIO33 红灯常亮 + GPIO4 闪光灯慢闪 + `Serial.println("A")`），可分别验证供电是否到达（灯）、TX→STM32 链路是否通（STM32 侧收到 "A"），无需 WiFi 参与。

#### 常见问题

- **STM32 收不到 READY**：确认 ESP32-CAM 已烧录配套固件；确认波特率 115200；**首先排除上方针脚陷阱（GND/R、VCC）**；确认 GND 共地。
- **重新插拔 CAM 后要不要按复位**：不用。STM32 每次抓拍前会自动重发 STATUS 握手；但 CAM 重上电需 10~20s 连 WiFi 才应答，此窗口内首次抓拍会 `failed (-1)`（CAM_OFFLINE），属预期，等几秒重试即可。
- **上电大灯（GPIO4 闪光灯）常亮**：上电瞬态 GPIO4 浮空所致，固件起来后自灭；只接 5V/GND 未接串口时属正常现象。
- **触发拍照无 URL 返回**：ESP32-CAM 需连接 WiFi 并能访问图床/服务器；检查串口日志。
- **ESP32-CAM 不断重启**：供电不足，5V 电流必须 ≥500mA。经 USB hub 供电时即使外接大功率电源也可能因瞬时压降触发 `Brownout detector was triggered`，满血固件（摄像头+WiFi）建议直插笔记本 USB 口或独立 5V/2A 电源；可降低 WiFi 发射功率（`WiFi.setTxPower(WIFI_POWER_8_5dBm)`）削减峰值电流。

### 2.5 DHT11 温湿度传感器

#### 接线

| DHT11 | 开发板 | 备注 |
|-------|--------|------|
| VCC | 3.3V | |
| GND | GND | |
| DATA | PG9 | 建议 4.7kΩ 上拉到 3.3V |

#### 常见问题

- **温度/湿度固定为 25.0/50.0**：传感器未接或读取失败，代码返回默认值。
- **读数偶尔为 0 或乱码**：数据线太长未加下拉/上拉；读取间隔太短（必须 ≥1.5s）。
- **校验和错误**：检查 DATA 线是否接触不良；确认 VCC 稳定 3.3V。

### 2.6 ADC 传感器（光敏 + MQ-2）

#### 接线

| 传感器 | 引脚 | 备注 |
|--------|------|------|
| 电位器 | PA5 / ADC1_IN5 | 备用，当前未使用 |
| 光敏电阻 | PF7 / ADC3_IN5 | 光照越强，ADC 值越小 |
| MQ-2 烟雾 | PA6 / ADC1_IN6 | 需 5V 供电；USE_MQ2=0 时跳过 |

#### 常见问题

- **光敏值不动**：检查 PF7 是否接对；确认光敏电阻方向正确。
- **MQ-2 始终为 0**：`USE_MQ2` 宏为 0 时正常；若已接线请改为 1，并确认 VCC=5V、预热数分钟。
- **ADC 值跳变剧烈**：多采样几次取平均；检查模拟地是否干净。

### 2.7 4×4 矩阵键盘

#### 接线

| 类型 | 引脚 | 模式 |
|------|------|------|
| 列输出 COL1~4 | PB7 / PA4 / PG15 / PC7 | 推挽输出 |
| 行输入 ROW1~4 | PC9 / PB6 / PE6 / PA8 | 上拉输入 |

#### 物理布局

```
1  2  3  A
4  5  6  B
7  8  9  C
*  0  #  D
```

#### 常见问题

- **按键无响应**：检查行列线是否接反；确认行输入有上拉；确认 `key_map` 与物理布局一致。
- **按 A 返回 B**：行列转置关系有误，检查 matrix_key.c 中的 `key_map` 和 GPIO 定义。
- **模式切换不灵敏**：主循环扫描间隔太长或阻塞；当前已实现非阻塞扫描。

### 2.8 LED 与蜂鸣器

#### 接线

| 设备 | 引脚 | 备注 |
|------|------|------|
| LED0 | PF9 | 低电平亮；同时用作 PWM 手机模式灯 |
| LED1 | PF10 | 低电平亮；入侵告警时亮 |
| LED2 | PE13 | 低电平亮 |

#### 常见问题

- **LED 不亮**：检查是否低电平点亮；确认 GPIO 已初始化。
- **蜂鸣器不响**：确认是无源蜂鸣器（需要 PWM）；有源蜂鸣器直接接 GPIO 即可。
- **告警时蜂鸣器只响一下**：检查主循环是否及时调用 `Beep_On()` 和 `Beep_Off()`。

### 2.9 独立看门狗 IWDG

#### 参数

- 时钟源：LSI 32kHz
- 默认超时：2s
- 喂狗函数：`IWDG_Feed()`

#### 常见问题

- **系统不断复位**：某处阻塞超过 2s 未喂狗；检查长等待循环（AT 应答、基线学习、FLASH 擦除）是否已分段喂狗。
- **热复位后上电即复位循环**：IWDG 跨热复位存活；凡 >1s 的裸 `delay_ms` 都是嫌疑对象（2026-09 实测：`ESP8266_Reset` 2s 等待、AT 基线学习 24s 均因此触发过）。
- **Debug 模式卡死**：ST 库函数版 IWDG 可能因 `assert_param` 死循环；当前已改用直接寄存器写。

### 2.10 RTC 实时时钟

#### 参数

- 时钟源：LSE 32.768kHz 优先，失败自动 fallback LSI
- 功能：日历时间 + 秒级 Wakeup Timer
- 关键约束：**PC13 与 RTC Tamper 复用，必须禁用 Tamper 才能给 OLED_CS 用**

#### 常见问题

- **RTC 时间不更新**：检查 LSE 晶振是否起振；看串口 `[RTC] OK, source=...` 日志。
- **OLED 初始化后黑屏**：RTC 抢占了 PC13 → 确认 rtc.c 中已禁用 Tamper。
- **Wakeup 中断不触发**：当前已改为主循环轮询读取 RTC 时间，不依赖中断。

### 2.12 板载按键 S1~S4（2026-09-21 实测修正）

#### 引脚与极性

| 按键 | 引脚 | 功能 |
|------|------|------|
| S1 | PA0 | 在家模式（HOME） |
| S2 | PE2 | 离家模式（AWAY） |
| S3 | PE3 | 睡眠模式（SLEEP） |
| S4 | PE4 | 短按=手动告警测试；长按 ≥1.5s=串口回放事件日志 |

**四个键全部低电平有效（含 PA0），全部配内部上拉**——这是实测结论：
课程模板注释称 "PA0=WK_UP 外部下拉、按下为高"，但 GEC-M4 这块板 PA0 实际带外部上拉
（配内部下拉时空闲仍读 1 可证），按下接 GND。极性判错会导致 PA0 被当成"一直按住"，
并在 if-else 优先级里把 S2/S3/S4 全部屏蔽（四键"全失灵"的典型根因）。
排障手段：`HandleBoardKey` 可临时加原始电平变化打印（KEYDBG），一键定位硬件/软件问题。

### 2.13 W25Q128 事件日志 FLASH

#### 接线

| 信号 | 引脚 | 备注 |
|------|------|------|
| CS | PB14 | 软件 SPI 模式 0 |
| SCK | PB3 | 注意是 JTDO 复用脚，调试器须 SWD 模式 |
| MISO | PB4 | NJTRST 复用脚，同上 |
| MOSI | PB5 | |

#### 常见问题

- **能读 ID（0xEF17）但擦写全部静默失败**：大概率是**写保护位遗留锁定**（共享课程板高发：
  之前有人做写保护实验留下非易失配置）。看开机日志三行：
  `[EVENTLOG] ID=0xEF17 SR1=.. SR2=.. SR3=..` → SR1 的 BP 位（0x7C）、SR2 的 CMP 位（0x40）、
  SR3 的 WPS 位（0x04）任一置位都会锁阵列；固件已自动清除并做"擦→写→读回"自检，
  `write selftest: PASS` 即恢复。SR3 的 WPS=1 最隐蔽：BP/CMP 全 0 也写不进。
- **记录数非零但回显 (empty)**：备份 SRAM 指针与 FLASH 脱节（跨固件烧录存活），
  固件会交叉验证并回退全扫描自愈，看到 `backup ptr stale vs FLASH, fallback to scan` 即此情况。

## 5. 问题排查优先级

1. **先看现象，再问软件**：量电压、看接线、确认模块型号
2. **再用卖家例程验证模块**：排除硬件损坏
3. **再看串口日志**：确认初始化顺序和错误信息
4. **最后改代码**：一次只改一处，改完编译+烧录验证
