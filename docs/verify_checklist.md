# SmartGuard 4 项修复 硬件实测清单

> 适用固件：2026-09-14 修复批次（Code=34660 / ZI-data=2468）
> 通用准备：串口助手打开 COM11 @115200（以实际端口为准）；板卡正常上电并完成 20s 基线学习。
> 已知时序背景：主循环伪时钟比真实时间慢约 16%（已知限制 #4），下表期望值均已按真实时间标注。

串口关键日志格式（来自源码）：

- 周期状态行（每 2s）：`[123s] L=2319 D=140.0cm T=26C H=39% | AWAY  | !!INTRUSION!!`
- 调试行（每 10s）：`[DBG] MQ2=360 th=400 T=26.0C dist_base=208.0`
- 告警行：`[ALERT] 入侵告警! 距离=35.2cm`
- MQTT 遥测（每 10s）：`T=26,H=39,D=140,L=2319,M=850`

## 修复 1：DHT11 读取失败保留旧值

**测什么**：DHT11 失效时温度/湿度保持上一次有效值，不归零。

**准备**：
- 串口打开 COM11 @115200
- 系统正常运行，状态行中 `T=` / `H=` 为有效值（如 `T=26C H=39%`）

**步骤**：
1. 记录当前状态行的 T/H 值（记为 T0 / H0）
2. 拔下 DHT11 数据线（PG9）
3. 观察后续至少 3 条状态行（约 6s）和 `[DBG]` 行
4. 插回 DHT11，观察 1~2 个决策周期（约 2~4s）

**观察点**：
- 拔掉期间：状态行 `T=` `H=` 应**保持 T0/H0**
- 不应出现 `T=0C H=0%`、`[DBG] ... T=0.0C`、遥测 `T=0,H=0`
- 插回后：T/H 应在约 2s 内恢复为实时值

**期望结果**：
- 拔掉期间 T/H 恒定 = 拔掉前最后一次有效读数
- 火灾检测不被跳过（不进入 `temperature <= 0` 分支）

**失败判断**：
- 拔掉后任何一条状态行出现 `T=0` 或 `H=0` → 修复未生效

**需保留的日志片段**：
- 拔掉前 1 条、拔掉期间 3 条、插回后 1 条状态行

## 修复 2：ML 距离偏差基准（dist_base）

**测什么**：`dist_base` 等于基线学习期 HC-SR04 到正前方静止墙面的平均距离。

**准备**：
- 串口打开 COM11 @115200
- 卷尺一把
- 传感器正前方为静止墙面，20s 学习期内无人走动

**步骤**：
1. 重新上电，等待基线学习完成（串口出现 `[AT] 基线学习完成`）
2. 等待 `[DBG]` 调试行出现（每 10s 一条），记录 `dist_base=X`
3. 用卷尺量 HC-SR04 到正前方墙面的实际距离 Y（cm）
4. 附加测试：断电重启，再观察 `dist_base` 的收敛过程

**观察点**：
- `[DBG] MQ2=... th=... T=...C dist_base=X` 中的 X
- 断电重启后：X 应在数秒内稳定到接近 Y（掉电恢复场景走"首样本播种"逻辑），或经 20s 重学后等于学习期均值（未走掉电恢复场景）
- X 不应为 0，也不应长期停在远离 Y 的值

**期望结果**：
- 判据：`|X - Y| < 20cm`
- 参考：训练集距离中位数为 208cm；你的环境以卷尺实测 Y 为准
- EWMA α=0.01，属于慢变量，上电 1 分钟内轻微漂移（几 cm）正常

**失败判断**：
- `dist_base=0` → 播种/采样链路未生效
- `|X - Y| >= 20cm` 且持续 1 分钟不收敛 → 修复未生效或学习期有遮挡

**需保留的日志片段**：
- `[AT] 基线学习完成` 起 3 条 `[DBG]` 行
- 卷尺实测值 Y 的记录

## 修复 4：入侵确认窗 3→2 次

**测什么**：从入侵发生到 `[ALERT]` 上报的延迟由约 4~6s 降为约 2~4s。

**准备**：
- 串口打开 COM11 @115200（建议开启串口助手的时间戳显示）
- 按 S2 切到 AWAY 模式（串口出现 `-> MODE AWAY` / `[MODE] AWAY`）
- 秒表或手机计时

**步骤**：
1. 站在传感器探测范围外（>120cm），等待状态行稳定显示 `OK`
2. 手快速伸到超声波正前方 <40cm 处并保持不动，同时记下时刻 t0（精确到 0.5s）
3. 记录 `[ALERT] 入侵告警!` 出现的时刻 t1
4. 延迟 = t1 − t0
5. 重复 5 次，取平均

**观察点**：
- 手到位后，状态行应经历约 1 个决策周期即出现 `!!INTRUSION!!` 和 `[ALERT] 入侵告警!`
- MQTT 侧（如有订阅）应同时收到 `ALERT:Intrusion!`

**期望结果**：
- 单次延迟在 **2~4s** 之间（= 0~2s 决策点对齐 + 2s 一个确认周期；叠加 16% 时钟偏差后实测上限约 4.6s）
- 5 次平均 ≤ 4s

**失败判断**：
- 延迟仍在 4~6s（实测 4.6~7s）→ 修复 4 未生效
- 出现手不靠近也频繁告警 → 2 次确认窗误报率不可接受，需评估回退或配合距离突变兜底参数调整（另行决策，不在本清单内）

**需保留的日志片段**：
- 每次测试从手到位前 1 条状态行到 `[ALERT]` 行的完整段落，共 5 段

## 回归测试（4 项全部通过后执行）

**目的**：确认修复未引入新问题。

1. **三模式切换**：依次按 S1 / S2 / S3，串口应依次出现 `-> MODE HOME` / `-> MODE AWAY` / `-> MODE SLEEP` 及对应 `[MODE]` 行；HOME 模式下入侵检测关闭（靠近不告警）
2. **手动告警**：AWAY 模式按 S4，应立即出现 `-> MANUAL ALERT TEST` 并在下一个决策点发出 `ALERT:Intrusion!`（MQTT），发完即清，不重复
3. **断电重启**：断电 5s 后重新上电，启动流程完整（横幅 → 硬件初始化 → 基线学习或掉电恢复 → `[MAIN] Entering SmartGuard main loop...`），无看门狗复位循环
4. **MQTT 遥测**：连续观察 1 分钟，应有约 5~6 条 `T=...,H=...,D=...,L=...,M=...` 遥测（标称 10s 一条，实测约 11.6s）
5. **静置误报观察**：AWAY 模式下传感器正对静止场景静置 10 分钟，`[ALERT]` 出现次数应为 0

**通过判据**：1~5 全部符合；任何一项异常 → 记录日志并回溯对应修复。
