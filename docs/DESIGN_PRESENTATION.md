# SmartGuard 智能空间守护系统 · 项目设计文档

> 验收答辩展示版。结构对齐《项目考核验收表》：设计目标 → 功能描述 → 设计方案 →
> 系统框架 → 实现过程 → 心得体会。每节末尾附【讲解要点】，供答辩时口头展开。

## 一、设计目标

基于 STM32F407ZE + FreeRTOS V10.5.1 设计并实现一套智能空间守护原型系统（保留裸机协作式调度回退）：

1. **感知**：通过多传感器融合，实时监测室内温湿度、光照、烟雾、距离、震动六路环境量；
2. **决策**：在端侧自主学习环境基线，识别**入侵、火灾、防拆**三类异常，解决传统报警器"阈值写死、误报多、断网失效"的通病；
3. **执行**：本地声光报警（分级告警音 + OLED 告警页），联动 ESP32-CAM 抓拍取证；
4. **上云**：手写 MQTT 协议上报云端，Web 看板远程监视与控制；
5. **可靠**：告警事件写入 SPI Flash 黑匣子断电不丢，看门狗 + 自愈机制保障 7×24 长期稳定运行。

【讲解要点】先讲三个通病（阈值写死/误报多/断网废），再给出设计立场："决策权和可靠性都放在端侧，网络只负责通知"。

## 二、功能描述

| # | 功能 | 说明 |
|---|---|---|
| 1 | 环境监测 | 六路传感器 2s 周期采集：温度、湿度、光照、烟雾（MQ-2）、距离（超声波）、震动（MPU6050） |
| 2 | 智能告警 | 20s 基线学习 + 3σ 自适应阈值 + EWMA 动态更新；端侧 MLP 神经网络处理模糊边界；连续确认窗 + 5s 冷却防误报刷屏 |
| 3 | 三种守护模式 | 在家（照明自动）/ 离家（全布防）/ 睡眠（关入侵防误报、保留火灾防拆），按键或远程切换 |
| 4 | 本地报警 | 分级告警音（入侵三连音/火灾双音/防拆长音）+ OLED 告警页整屏抢占 + LED |
| 5 | 远程监控 | Web 看板：实时数据卡片、告警时间线（聚合+筛选）、7 天分层历史曲线、远程控制（灯/模式/抓拍/告警测试） |
| 6 | 入侵抓拍 | 告警触发 ESP32-CAM 拍照，照片 URL 经 MQTT retain 回推；网页胶片条回看 12 张历史 + MJPEG 实时画面 |
| 7 | 事件黑匣子 | 告警事件（时间戳+传感器快照）写入 W25Qxx 环形日志 1024 条，断电不丢，S4 长按可串口回放 |
| 8 | 掉电恢复 | 配置存 EEPROM（magic+CRC32），合法则跳过 20s 学习直接上岗；RTC 纽扣电池走时 + NTP 对时 |

【讲解要点】按"感知→决策→告警→取证→落盘"的闭环顺序讲，别逐条念表。

## 三、设计方案

### 3.1 总体架构：分层解耦

软件采用 **"Hardware 驱动层 + APP 应用层"分层架构**：

- **驱动层**：独立完成 GPIO / ADC / USART / TIM（PWM+输入捕获）/ 软件 I2C / 软件 SPI 等 10 余类外设驱动，一模块一目录，低耦合可移植；
- **应用层**：`SensorHub` 将六路数据统一聚合为 `Sensor_Data_t` 结构体，决策层只面对结构体——换传感器不改决策代码；
- **容错设计**：未接线/故障模块初始化自动跳过，单点失效不拖垮整机。

### 3.2 调度架构：FreeRTOS 抢占式多任务（可回退裸机）

- 当前实现：FreeRTOS V10.5.1，1 kHz tick，5 个任务抢占调度——fast（4，50 ms 按键+喂狗）/ tamper（3，200 ms 防拆）/ decision（2，1 s 采样+决策）/ comm（2，50 ms 轮询网络）/ display（1，500 ms OLED）；
- 任务间用事件队列（深度 8）传递模式与告警事件；AT24C02/MPU6050 共用 I2C 总线用互斥锁串行化；ESP8266/CAM 串口访问收敛到 comm 单任务；
- 中断服务程序不调用 FreeRTOS API，NVIC 分组 4；空闲钩子 `__WFI` 休眠；
- 回退机制：`USE_FREERTOS=0` 即回到协作式调度器（任务表注册，SysTick 1 ms，周期零漂移）。两种模式共用业务函数体。

### 3.3 决策架构：三级分流（本项目的 AI 体现）

| 级 | 判据 | 负责区间 | 理由 |
|---|---|---|---|
| 硬规则 | 绝对阈值（如 D<40cm） | 确定的异常 | 可解释、零成本、永不出错 |
| 自适应基线 | 20s 学习 μ±3σ + EWMA(α=0.01) 慢跟随 + 大偏离拒绝吸收 | 统计显著偏离 | 换房间免重调；防"入侵者教会系统" |
| TinyML | sklearn MLP 10→16→8→1，10 维特征，端侧推理 | 40~80cm 模糊边界 | 规则说不清的交给数据；485 样本为历史 TF 管线报告，当前 sklearn 管线指标以重跑 `v1_train/train_sklearn.py` 为准 |

入侵另设**连续 2 次命中确认窗**（≤8cm 当周期直通）；火灾采用烟雾+温度双条件、迟滞带与连续 4 样本确认；防拆采用 8 格滑窗 ≥3 次投票——三道独立防线对应三种误报来源。

### 3.4 通信架构：手写 MQTT + retain 双向同步

- ESP8266 仅 AT 透传通道，无 SDK 可用 → **手写 MQTT 3.1.1 报文**（CONNECT/SUBSCRIBE/PUBLISH/PINGREQ，QoS0）；
- 下行 `+IPD` 两级状态机逐字节解析（剥前缀、解包、长度越界卫兵），实测命令 19/19 全响应；
- **retain 状态同步**：固件每次会话就绪即上报最新灯态/模式，新订阅者连上立得真实状态，不轮询不靠猜；
- **流量整形**（flood 事故后加固）：Web 端 300ms 命令节流 + 固件上报 500ms 合并（最终一致补报）+ CAPTURE 5s 硬限速。实测 20 条 flood → 仅 2 条上报、最终态收敛、会话 2s 自愈。

### 3.5 存储架构：按介质特性选型

| 数据 | 介质 | 设计 |
|---|---|---|
| 基线/模式配置 | AT24C02 EEPROM | 单字节擦写适配高频小改；magic + CRC32 防撕裂 |
| 告警事件 | W25Q128 SPI Flash | **环形追加写**：16B/条只追加不擦除，1024 条写满整体覆盖——绕开"整块擦除"限制，寿命提升三个数量级；开机自检 + 写后读回 + 备份指针交叉验证 |
| 时间 | RTC + VBAT 备份域 | 纽扣电池掉电走时；NTP 对时为主、编译时间兜底 |

### 3.6 可靠性设计：按失效模式反推

| 失效模式 | 对策 |
|---|---|
| 程序跑飞 | IWDG 2s 看门狗；所有长等待（ESP8266_Reset 等）分段有界喂狗 |
| 网络中断 | MQTT 自动重连（60s 退避）+ 重连后自动重报状态；重连阻塞期防拆采样 WaitHook 续采 |
| 写一半断电 | magic+CRC32 校验不过自动重建；事件日志写后读回 |
| 存储被锁 | SR1/SR2/SR3 写保护自诊断 + 自动解除（BP/CMP/WPS 全覆盖） |
| 命令洪峰 | 三层防线（见 3.4），实测数据支撑 |

【讲解要点】3.3 和 3.4 是得分主战场，各给 60 秒；其余一节 20~30 秒带过。每个设计都能说出"为什么这么选"。

## 四、系统框架

```
┌───────────────────────── SmartGuard ─────────────────────────┐
│                                                              │
│  感知层   光敏PF7·MQ-2 PA4·DHT11 PG9·HC-SR04 PC8/6·MPU6050   │
│              ↓ SensorHub → Sensor_Data_t                     │
│  决策层   自适应阈值(基线+3σ+EWMA) → 模式状态机(HO/AW/SL)     │
│           → TinyML MLP(模糊边界)                              │
│              ↓ Alert_Type_t                                  │
│  执行层   蜂鸣器PF8(PWM) · OLED(SPI) · LED · USART1 日志      │
│                                                              │
│  调度守护 FreeRTOS V10.5.1 抢占调度(5 任务) · IWDG 2s      │
└──────────┬──────────────────────┬────────────────────────────┘
           │ USART3(AT透传)        │ USART2(拍照指令)
           ↓                      ↓
      ESP8266 WiFi          ESP32-CAM
           │ MQTT 3.1.1(手写报文)   │ HTTP(/shot.jpg /stream)
           ↓                      ↓
      mosquitto broker ──────→ Web 看板 (Vue3+Pinia+ECharts)
      (1883 TCP / 9001 WS)    实时数据·告警时间线·抓拍胶片条·远程控制

持久层：AT24C02(配置,magic+CRC32) · W25Qxx(事件环形日志1024条) · VBAT RTC
```

**数据流实例（入侵告警全链路）**：

```
人靠近 → 超声波距离突变 → 连续3次命中确认 → 决策引擎判 INTRUSION
→ 蜂鸣器三连音 + OLED 告警页 + LED
→ 串口指令 CAM 拍照 → 照片 URL 经 MQTT retain 回推
→ Web 看板红闪 + 时间线新增"入侵" + 胶片条出新图
→ 事件(时间戳+光照/烟雾/距离快照) 追加写入 W25Qxx 黑匣子
```

【讲解要点】框架图先指四个角色（主控/通信/视觉/看板），再走一遍数据流实例——老师要看到的是"闭环"。

## 五、实现过程

按"骨架 → 驱动 → 算法 → 通信 → 存储 → 视觉 → 加固"七步推进，每步都有典型问题与解决：

| 阶段 | 工作 | 典型问题与解决 |
|---|---|---|
| 1. 骨架 | 工程搭建、SysTick 节拍、协作式调度器、编译警告 13→0 | 早期估算式主循环时漂 16% → 改任务表调度，周期基于真实 g_tick |
| 2. 驱动 | 六路传感器 + OLED + 蜂鸣器 + 按键逐个联调 | 按键极性与课程模板注释不符（PA0 实为低有效）→ 打印原始电平实测修正；超声波超时 D=0 致误报 → 决策层定义为无效样本 |
| 3. 算法 | 自适应阈值、确认窗、冷却、TinyML 部署 | 火灾阈值两处写入点不一致，运行期漏 400 下限致阈值塌缩 → 统一 `max(ewma+3σ, 400)`；TF 与 sklearn 管线符号冲突 → 砍掉 TF 管线统一 sklearn |
| 4. 通信 | 手写 MQTT、下行解析、retain 双向同步 | AT 应答循环与 SEND OK 等待窗吃掉下行 +IPD 帧 → 5 处改"字节一到就喂解析器"，19/19 全响应 |
| 5. 存储 | EEPROM 配置、W25Qxx 事件日志、备份 SRAM 指针 | 日志写不进：分层诊断（驱动→BP→CMP）定位 **SR3 WPS=1 独立块锁**（共享课程板遗留非易失配置）→ 加自诊断+全局解锁+写自检，selftest PASS |
| 6. 视觉 | CAM 抓拍回推、历史环、Web 胶片条 + LIVE | Chrome `<img>` 不关 MJPEG 长连接占死单客户端 CAM → 改 fetch+AbortController 逐帧解析 + 拉流代数守卫 |
| 7. 加固 | flood 三层防线 | 网页连点 LED 打挂会话（"离线却可控灯"）→ 串口日志复盘事故链 → Web 节流+固件上报合并+限速；实测 20 条 flood → 2 条上报、2s 自愈 |

验证手段：串口日志分级（INIT/DBG/ESP/MQTT）、J-Link SWD 在线调试（halt 读 PC/栈/复位寄存器）、`build_verify.bat` 全量重建+时间戳审计防陈旧构建假阳性。

【讲解要点】七步里挑 3、5、7 展开（算法坑、存储锁、flood 事故）——有事故链、有定位过程、有实测数据的才是好故事。

## 六、心得体会

1. **排障方法论**：本项目每个疑难问题（按键极性、Flash 写锁、flood 假死）都靠"现象 → 假设 → 分层验证 → 修复 → 文档"闭环解决。串口日志和 J-Link 在线调试是嵌入式开发者的眼睛——会看 PC/栈/复位寄存器，就没有定位不了的卡死。
2. **可靠性是设计出来的**：自适应算法降误报、存储校验自愈、看门狗有界等待、流量整形——这些"不出事就看不见"的部分，正是产品级系统与 demo 的区别。失效模式反推设计，比功能堆砌更能体现工程能力。
3. **端侧智能的价值**：把决策（含 TinyML 推理）放在本地，系统才具备断网可用的韧性；规则与 AI 分层协作，兼顾可解释性与模糊判断力。
4. **设计者视角**：每个技术选型都要能回答"为什么这么选、代价是什么"——环形追加写之于 Flash 擦除限制、retain 之于状态同步、QoS0 之于遥测，都是约束条件下的权衡而非照抄方案。

【讲解要点】心得别念稿，用一句话收："这个项目教会我的不是把功能调通，而是为'没人盯着的系统'做设计。"
